How to check if an update slowed down your Linux PC

You updated, and now games stutter or builds feel slower. Maybe the update did it, or maybe it's something else. Here's a simple, fair way to find out, without guessing.

Why updates can change performance

On a rolling-release system like CachyOS or Arch, one update can bring a new kernel, a new graphics driver, a new Mesa, and dozens of library updates at once. Any of them can change how fast your PC feels: a scheduler change in the kernel, a driver bug, a new default power setting, or a compiler change in a package you use every day.

Many slowdowns right after an update are temporary, though. The first boot after a big update often rebuilds shader caches, re-indexes files (KDE's file search, for example) or recompiles kernel modules with DKMS. So the first rule is: don't judge the first few minutes.

Step 1: Have a "before" number

You can't prove something got slower without knowing how fast it was. Before you update, run a short set of benchmarks and write down the results along with your versions. These commands show the versions that matter most: 

uname -r
pacman -Q mesa nvidia-utils 2>/dev/null
powerprofilesctl get 2>/dev/null

If you already updated and have no "before" number, you can still compare against an older kernel or a downgraded package (Step 4).

Step 2: Test the same way every time

Benchmarks are noisy. To get numbers you can trust:

  • Same conditions. Plugged in, same power profile, same monitor setup, nothing big running in the background.
  • Start cool. A warm CPU or GPU boosts less. Wait a few minutes after a game or build, and check temperatures with sensors.
  • Wait after boot. Give the system a few minutes to finish start-up jobs and cache rebuilds.
  • Run it more than once. Do two or three runs and look at the spread. If runs differ by 3% from each other, a 2% change after an update means nothing.
  • Use the same tests. The same tool, the same settings, the same test file. Change one thing at a time.

Step 3: Find out what actually changed

pacman keeps a log of every package it installs, upgrades or removes. This shows the most recent upgrades: 

grep -E "upgraded|installed|removed" /var/log/pacman.log | tail -n 40

Look for the big ones first: linux-cachyos (or your kernel), nvidia or mesa, plasma or your desktop, and anything related to the program that got slower.

Step 4: Narrow it down

  • Try another kernel. Many CachyOS and Arch setups keep a second kernel (like an LTS kernel). Boot it from the boot menu and run the same tests. If the old speed comes back, the kernel is your suspect.
  • Downgrade one package. Older versions usually sit in /var/cache/pacman/pkg/. Install one with sudo pacman -U /var/cache/pacman/pkg/<package-file>, re-test, and upgrade again when you're done.
  • Use a snapshot. If you use Btrfs snapshots (Snapper or Timeshift), you can roll back the whole system, test, and roll forward again.

Only change one thing per test, or you won't know which change mattered.

Step 5: Decide, and report it

If a change is real and repeatable, you have three choices: keep the update and live with it, hold the package back for now, or report it. A good bug report includes the old and new package versions, your hardware, the exact test you ran, and the before and after numbers. Developers can act on that. "It feels slower" is much harder to fix.

Doing this the easy way

All of this works by hand, but it's tedious, so we built CachyOS Benchmark to do it for you. It's free and open source. It tracks performance changes between system updates on CachyOS and other Arch-based systems: it runs the same tests every time (CPU, memory, compression, video encoding, disk, GPU and latency) and saves each run with your kernel, NVIDIA, Plasma and Mesa versions. Its What changed view reads the pacman log, lists the packages that changed since your last run, and marks which scores moved more than normal run-to-run noise. It also warns you when a run starts with the PC already hot.

Run it once now to save a baseline, then again after your next update. If something got slower, you'll see it, and which update came with it.
